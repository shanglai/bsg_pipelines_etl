01

¿Qué es un pipeline de datos?

Del script que corre en tu laptop al sistema del que depende el negocio

Conceptos

Definición

Un pipeline de datos es un sistema que mueve datos desde sus fuentes hasta quienes los consumen, transformándolos en el camino, de forma automática, repetible y observable.
automáticorepetibleobservable

Si falta cualquiera de las tres, tienes un script… todavía.

Preguntar: ¿quién tiene un script que corre cada mañana a mano? Ese es el punto de partida de la mayoría de los pipelines.
Conceptos

Script vs pipeline

PreguntaScriptPipeline
¿Quién lo ejecuta?Una persona, cuando se acuerdaUn orquestador, por horario o por evento
¿Si falla a la mitad?Datos a medias; nadie se enteraReintenta, alerta y no deja archivos corruptos
¿Si lo corro dos veces?Duplica registrosMismo resultado: es idempotente
¿Cómo sé que funcionó?Lo reviso a manoMétricas, logs y validaciones de calidad
¿Si crece el volumen?Se vuelve lento o se rompeEscala por diseño (incremental, particionado)
Anti-patrón clásico: except Exception que devuelve un DataFrame vacío. El pipeline 'termina bien' y el tablero amanece en ceros.

Buenas prácticas

Seis propiedades no negociables

Idempotente

Correrlo n veces produce lo mismo que correrlo una vez.

Reprocesable

Puedo recalcular un periodo pasado (backfill) sin romper nada.

Atómico

O termina completo o no deja rastro: nada de archivos a medias.

Observable

Sé qué corrió, cuánto tardó y qué tan frescos están los datos.

Probado

Pruebas de código y validaciones de datos en cada corrida.

Seguro

Secretos fuera del código y mínimo privilegio en cada conexión.

Pedir un ejemplo real de cada una. La idempotencia es la más importante para ingeniería de datos y la más ignorada.
Buenas prácticas

Idempotencia en una imagen

No idempotente

-- Cada corrida agrega otra copia del día
INSERT INTO ventas
SELECT * FROM staging_ventas
WHERE fecha = '2026-09-28';

Segunda corrida = ventas del día duplicadas.

Idempotente

BEGIN;
DELETE FROM ventas
WHERE fecha = '2026-09-28';
INSERT INTO ventas
SELECT * FROM staging_ventas
WHERE fecha = '2026-09-28';
COMMIT;

Reemplaza la partición completa dentro de una transacción.

Otra variante es MERGE/upsert por llave. Lo profundizamos en la sesión 1.3 (cargas incrementales).

Modos de operación

El espectro de latencia

Elige la latencia que el negocio necesita, no la que suena más moderna.

Pregunta clave para el negocio: ¿qué decisión cambia si el dato llega en 1 segundo en lugar de 1 hora? Si ninguna, es batch.
Modos de operación

Streaming no es lo mismo que eventos

Streaming

Procesa un flujo continuo y mantiene estado: ventanas de tiempo, conteos, agregados. Ejemplo: compras por tarjeta en los últimos 5 minutos.

Por eventos

Reacciona a un hecho individual, normalmente sin estado. Ejemplo: al llegar un CSV, validarlo y cargarlo.

Ambos usan mensajería (Kafka, Pub/Sub, Kinesis), por eso se confunden. La diferencia es si necesitas estado a lo largo del tiempo.

Modelos de cómputo

VM, contenedor o serverless

Mientras más arriba sube la línea de lo que administra el proveedor, menos control y menos operación. El contenedor es el punto medio: tú defines la imagen.

Un pipeline tranquilo con Luigi en Colab

Laboratorio

¿Por qué Luigi?

  • Orquestador ligero creado por Spotify.
  • Corre dentro del notebook: sin servidor ni base de datos.
  • Tres conceptos: requires(), output() y run().
  • Regla de oro: si la salida existe, la tarea no se repite.

Airflow llega en el Capítulo 3; hoy solo queremos ver las etapas.


class Transformar(luigi.Task):

    def requires(self):          # arista del DAG
        return ExtraerDetalle()

    def output(self):            # "terminé" = existe
        return luigi.LocalTarget(
            "silver/pokemon.parquet")

    def run(self):
        df = aplanar(self.input())
        with self.output().temporary_path() as tmp:
            df.to_parquet(tmp)   # escritura atómica
Laboratorio

Qué construyes

Laboratorio

Instrucciones y retos

Pasos

  1. Abre Lab_1_1_Pipeline_Luigi.ipynb en Colab.
  2. Ejecuta las celdas en orden hasta el tablero.
  3. Si la API no responde, usa MODO_OFFLINE = True.

Retos

  1. Idempotencia: corre dos veces; luego borra top10.csv. ¿Se regeneró?
  2. Falla controlada: activa SIMULAR_FALLA. ¿Qué llegó a gold?
  3. Opcional: agrega la tarea TopPeso.
Tiempo: 20 minutos. El modo offline genera datos sintéticos con semilla fija, con la misma estructura que la API. El reto 1 tiene truco: Luigi evalúa desde el final hacia atrás; como el tablero existe, ni siquiera revisa TopPokemon.

Resumen

Para llevar

  1. Un pipeline es automático, repetible y observable; si no, es un script.
  2. El ciclo de vida: generación → ingesta → transformación → servicio, sobre almacenamiento.
  3. Elige batch, streaming o eventos por la latencia que el negocio necesita.
  4. OLTP opera, OLAP analiza; el lakehouse une lake y warehouse.
  5. Los conceptos son iguales on-premise, en GCP y en AWS; cambian nombre, operación y cobro.
